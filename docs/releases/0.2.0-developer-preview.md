# AgentCI 0.2.0 Developer Preview

Status: **Developer Preview / Sandbox Alpha**. This is not a security certification of any sandbox backend.

## What is delivered

AgentCI 0.2.0 Developer Preview makes the current sandbox evidence foundation usable through installed CLI surfaces:

```bash
agentci sandbox doctor [--json]
agentci sandbox verify <evidence.json> [--json] [--print-digest]
agentci sandbox verify <evidence.json> --receipt <manifest.json> --receipt-bundle <sidecar-dir> [--json]
```

`doctor` performs bounded local readiness/discovery. Readiness is not backend execution, not isolation proof, and not a security certification.

`verify` validates one canonical S0 `EvidenceEnvelope` using AgentCI's fail-closed evidence contract and the same canonical validator semantics used by the repository regression suite.

The opt-in receipt form additionally validates an exact, non-recursive signed fixture observer/cleanup bundle and writes a self-contained content-addressed manifest. Replay uses verifier-pinned public fixture trust; keys inside user input or receipt metadata cannot replace that policy. The receipt remains `certification_claim=false` and is not provider execution proof or provider-native attestation.

## Evidence validity is not PASS

**Valid evidence is not a security certification and is not equivalent to a PASS verdict.**

The verifier reports both:

- `recorded_verdict` — the verdict carried by the evidence envelope;
- `expected_verdict` — the verdict recomputed by the canonical validator.

A canonical red-control envelope can correctly be:

```text
valid = true
recorded verdict = FAIL
expected verdict = FAIL
certification claim = false
```

That means the evidence faithfully proves a failure. It does not mean the sandbox passed.

Malformed, tampered, stale, ambiguous, or incompletely bound material evidence remains invalid/non-PASS. Missing material observability remains `UNVERIFIED` rather than being promoted to success.

## Installed-package gate

The Developer Preview ships the canonical validator code and exact schema/TestCase/attestation/receipt-profile resources needed for verification from an installed wheel. CI builds a wheel, installs it into a fresh virtual environment, changes working directory outside the repository checkout, and runs both `sandbox doctor` and `sandbox verify`.

This gate exists because repository-local imports are not sufficient evidence that a shipped CLI works.

## What is not delivered

0.2.0 does **not** claim:

- any provider/backend is certified or secure;
- provider-native hardware/runtime attestation;
- real cross-backend containment certification;
- autonomous privilege expansion;
- a released `agentci sandbox certify` command;
- production key-custody/anti-replay guarantees;
- automatic Verified Execution backend selection/execution.

These remain later evidence gates. Unsupported material dimensions must remain `UNVERIFIED`.

## Security invariants retained

- Observation != Authority.
- Configured != verified/effective.
- Backend name != security verdict.
- Missing observability != PASS.
- Privilege contraction != expansion.
- Expansion requires external authenticated authority.
- Restore != clean restart.
- Execution status != backend verdict.
- Deny-everything does not prove useful containment without authorized utility.
