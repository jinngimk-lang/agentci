# AgentCI 0.2 Developer Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the already-reconciled Sandbox Program as an installable, fail-closed AgentCI 0.2 Developer Preview by adding installed S0 evidence verification, wheel-safe canonical resources, synchronized discovery, and a post-merge release gate.

**Architecture:** `main` already contains the reconciled S0 schema/validator and the independently challenged `agentci sandbox doctor`. Keep that S0 validator as the single implementation and ship its runtime dependencies/resources into the wheel rather than reimplementing verdict logic. Expose a thin `agentci sandbox verify` adapter that distinguishes “valid evidence envelope” from the envelope’s security verdict.

**Tech Stack:** Python 3.11+, argparse, jsonschema, setuptools, pytest, GitHub Actions.

## Global Constraints

- Provider/backend names are provenance only, never a security verdict.
- `UNVERIFIED` may not be promoted to PASS because configuration, discovery, or observability exists.
- No destructive host probes, escape tests, provider ranking, real secret collection, or unsupported certification claims.
- One canonical S0 schema/validator only; package resources are shipping mirrors guarded by byte-parity tests, not a second IR.
- `Fixer != Merge Decider`; release-critical changes require a non-author challenge and exact-head merge protection.
- Public label remains **Developer Preview / pre-alpha / not a security certification**.
